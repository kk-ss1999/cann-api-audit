# 代码仓与官方接口文档核对

输入 **一个代码仓 + 一个官方接口文档入口**，找出代码仓直接使用的该产品接口，按名称与官方文档比对，输出 Markdown 报告。

依赖对象由文档入口决定。你无需额外指定产品名称、模块名或识别规则；执行 skill 的 AI 助手会从官方文档中确认这些信息，再扫描源码和复核结果。

## 提供什么

| 输入 | 说明 |
| --- | --- |
| 代码仓 | 本地目录、仓库子目录或远端 Git URL |
| 官方文档入口 | 要核对的产品的官方 API 参考，或可导航到 API 的产品文档目录 |
| 报告路径（可选） | Markdown 文件保存位置；未指定时选择被扫描仓库之外的目录 |

例如，代码仓搭配 PTA 官方文档，就核对该仓库直接使用的 PTA 接口。换成另一产品的官方文档，识别对象和规则也随之更换。

## 怎么用

需要能够读取文件、运行 Python/Git 和访问官方文档的 AI 助手，以及 Python 3.10+、Git。扫描脚本只使用 Python 标准库，无须安装被扫描项目的依赖。访问远端私有仓库需要已有访问权限。

下载 skill：

```sh
git clone https://github.com/kk-ss1999/cann-api-audit.git
```

让助手读取下载目录里的 `SKILL.md`，然后提供两个输入：

```text
请读取 <下载目录>/cann-api-audit/SKILL.md，按其中的流程执行。
代码仓：<本地目录或远端 Git URL>
官方文档入口：<要比对的官方接口文档链接>
输出 Markdown 报告。
```

如果已安装到助手的 skills 目录，可以直接调用：

```text
使用 $cann-api-audit：
代码仓：<本地目录或远端 Git URL>
官方文档入口：<要比对的官方接口文档链接>
报告保存到：<报告目录>/api-report.md
```

仓库名和调用名 `cann-api-audit` 是现有标识，功能不限于名称中的产品。

## 会做什么

1. 阅读官方入口，确认产品、版本、API 目录，以及有官方依据的模块、命名空间和符号规则。
2. 扫描代码仓的直接接口引用，检查导入别名、动态绑定、宏和本仓同名定义等情况。
3. 将接口名称与所选版本的官方 API 正文核对，保留所属模块或类，避免同名误匹配。
4. 复核未匹配项及覆盖缺口，输出接口清单、源码位置和文档证据。

入口指定版本时使用该版本；`latest` 解析为实际版本；未指定版本时通过官网导航确认最新版本。无法确定产品、版本或完整读取文档时，会说明缺口并保留待核实状态。

## 报告内容

| 状态 | 含义 |
| --- | --- |
| 已匹配 | 已确认目标归属，并找到该版本官方 API 正文证据 |
| 官方文档未找到 | 已确认直接依赖，完成文档覆盖复核和二次检索后未找到接口名称 |
| 待核实 | 接口归属、源码覆盖或文档获取仍有缺口 |

每个接口保留名称、全部源码位置；匹配项附官方文档链接。报告记录代码仓 commit、实际依赖对象、文档入口、版本和覆盖状态，不展示内部识别线索。

伴随生成的 JSON 用于助手复核和复现，不需要用户填写或维护。

## 范围和边界

- 扫描正式源码、测试、示例、文档代码块，以及构建和配置中的直接引用；本地包含未提交内容。
- 覆盖函数、类型、结构体、枚举及枚举值、宏、常量、类和方法。
- 只检查仓库直接使用的目标接口，不追踪第三方组件内部的间接调用。
- 排除普通上下文词法、纯本地实现、其他组件接口，以及仅注释或说明文字中的名称。
- 按名称核对，不检查参数、签名或运行时兼容性。
- “官方文档未找到”仅针对本次已核实的文档范围，不直接判定为内部接口。

## 执行方式和验证范围

这是由 AI 助手执行的 skill。助手负责理解不同官网、整理识别规则与正文快照，脚本负责候选提取、名称匹配及报告生成。通用脚本本身不能仅凭 URL 自动理解和抓取任意官网。

基础扫描支持 Python 导入和别名引用、C/C++ 限定名及有文档依据的符号规则。宏展开、动态绑定、实例方法、其他语言和配置需助手补查；扫描器成功退出不代表审计完成。不同官网的可读性和目录完整性需要在实际执行时验证。

CANN 有专用获取适配，其范围限于“API参考、算子库、通信库、加速库”，规则见 [专用适配说明](references/cann.md)。该范围限制不套用到其他产品。PTA 的通用流程已有模拟样例测试，尚未完成真实 PTA 官网的端到端审计。
