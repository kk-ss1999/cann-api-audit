# 官方接口依赖核对

提供 **本地/远端代码仓 + 官方接口文档入口**，skill 自动识别依赖对象、整理有官方依据的识别规则，找出代码仓直接使用的接口，与指定官方文档按名称核对，生成 Markdown 报告。支持 CANN、PTA 等依赖对象。

## 怎么用

需要 Python 3.10+、Git，以及读取代码仓和官方文档的网络权限。扫描脚本仅使用标准库，无须安装被扫描项目依赖。

```sh
git clone https://github.com/kk-ss1999/cann-api-audit.git
```

将目录放到助手的 skills 目录，或让助手读取下载目录里的 `SKILL.md`。调用名称仍为 `$cann-api-audit`。

给助手发送：

```text
使用 $cann-api-audit：
代码仓：D:\Ascend\Projects\vllm-ascend
官方文档入口：<粘贴 PTA 官方文档入口>
报告保存到 D:\reports\pta-api-report.md。
```

代码仓也可以是远端 Git URL：

```text
使用 $cann-api-audit 核对 https://github.com/example/project.git
对官方文档 <粘贴官方文档入口> 所属产品的直接接口依赖。
输出 Markdown 报告。
```

不用填写产品名称、模块名或规则 JSON。助手先从官方入口识别产品、版本和 API 范围，再根据官方说明与源码导入、命名空间、动态绑定等确定接口归属。产品无法确定或入口不可读时会说明缺口。

## 核对范围

- 输入：本地目录或远端 Git URL，以及官方接口文档入口。
- 源码：正式源码、测试、示例、文档代码块、构建和配置中的直接引用。
- 接口：函数、类型、结构体、枚举及枚举值、宏、常量、类和方法。
- 文档：入口指定的官方版本；latest 解析到实际版本；无版本入口通过官网导航确认最新版本。
- 标准：相同接口名称被官方 API 正文收录，保留类/模块归属；不核对签名或运行时兼容性。
- 边界：不追踪第三方内部间接调用，不收集普通上下文词法；纯本地实现、其他组件、仅注释的名称不进入报告。

核对 PTA 时，其官方文档确认的 `torch_npu` 接口可以是直接依赖；核对 CANN 时，不追踪 `torch_npu` 内部的 CANN 调用。识别规则由文档对象决定。

CANN 的官方证据限定为“API参考、算子库、通信库、加速库”，排除编程语言、调试工具、基础数据结构和接口、应用开发等其他章节。此限制仅适用于 CANN。

## 报告内容

| 状态 | 含义 |
| --- | --- |
| 已匹配 | 已确认目标归属，并有该版本官方 API 正文证据 |
| 官方文档未找到 | 已确认直接依赖，完成文档覆盖与二次检索后未找到名称 |
| 待核实 | 接口归属、源码覆盖或文档获取仍有缺口 |

报告保留接口名称、全部源码位置、官方文档链接，以及仓库 commit、实际产品/版本和覆盖状态，不展示内部识别线索。未找到不代表必然是内部接口；无异常条目也不能替代覆盖复核。

建议报告保存在被扫描仓库之外。伴随 JSON 是助手用于复核和复现的内部资料，无需用户维护。

## 工作方式与限制

通用 skill 由助手读取不同官网并生成规则与正文快照，再调用脚本扫描和匹配。**通用脚本本身不具备仅凭 URL 自动理解、抓取任意官网的能力**；动态网站、PDF、目录完整性和产品归属由助手核实。

基础扫描支持 Python 导入和别名引用、C/C++ 限定名及文档证实的符号规则。宏展开、动态绑定、实例方法、其他语言和配置需助手补查；扫描器成功不等于审计完成。文档或源码存在未核实缺口时输出阶段性报告。
